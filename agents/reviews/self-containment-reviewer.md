# self-containment-reviewer — Performance Log

## 2026-06-23 — Created (sonnet)
- Role: Read-only quality-gate reviewer that verifies every committed-facing artifact in the diff (code comments, CLAUDE.md, committed docs, test descriptions, fixture strings) is self-contained — understandable by a brand-new engineer with zero access to the author's local `notes/` and zero memory of the ticket's private session history. Flags leaked `notes/` paths, internal plan-label shorthand (C1/C2/C3, D1/D2, "Option A"), private process/history references ("the redirect", "per the plan"), reviewer/person names, and dangling context.
- Model rationale: The core job is semantic judgment, not pattern-matching — deciding whether a token only resolves for someone who read the author's private notes, and discriminating legit domain/language vocabulary (TS generics `T1`, HTTP `404`, `AWS S3`, Jira keys) from private labels. A regex commit hook already exists and provably misses both semantic leaks and grandfathered-in labels; the whole reason for a reviewer is the judgment a cheaper tier cannot supply. Haiku rejected — it over-flags legit terms and under-flags semantic leaks, and cannot reliably make the ambiguous→LOW discrimination. Sonnet matches the four sibling judgment reviewers (code-reviewer, edge-case-qa, code-smells-reviewer, test-reviewer). Opus rejected — this is applying a fixed five-category taxonomy to inlined text, not novel architecture.
- Effort: high — matches the sibling sonnet reviewers; the false-positive discrimination (is this `T1` a type param or a plan label?) and the verify-before-flag pass benefit from deeper reasoning, and a missed leak ships to a customer/teammate-facing artifact. (Flagged to Parker as a dial-down-to-medium confirm item if cost matters.)
- Tools: Read Grep Glob (read-only; matches all sibling reviewers). Inline-context contract: the agent works from the inlined diff and is told NOT to use Read at runtime; Read/Grep/Glob remain granted only as a rare targeted fallback for confirming an in-file antecedent.
- permissionMode: dontAsk
- maxTurns: 15 — matches code-reviewer / edge-case-qa. Lower than test-reviewer/code-smells (50) because this agent never needs to read production bodies for cross-referencing; the leak is visible in the changed text itself. Expected 0–3 tool calls per the inline-context contract.
- Severity model: deliberately two-tier (MUST-FIX default / LOW for ambiguous), NOT the critical/high/medium/low of the other reviewers. Per Parker's mandate: self-containment is binary enough that a confirmed leak must block, and LOW is reserved for genuine judgment calls. Integrates with the existing gate because the orchestrator routes ALL actionable findings into the 4d fix-cycle with explicit user deferral — there is no severity-threshold gate to change. (Flagged to Parker as a confirm item.)
- Intended use: 6th parallel reviewer in the Step 4c quality gate, alongside code-reviewer, acceptance-qa, edge-case-qa, code-smells-reviewer, test-reviewer. Runs on standard, lightweight, AND docs-only workflows — doc/comment leaks happen on small and docs-only diffs too (the motivating live incident was a leftover `C2`/`C3` label in a shipped service comment caught by a human reviewer on a PR).
- Status: Created and wired but NOT yet live — pending orchestrator + Parker review of the build report. Open confirm items: (1) agent name (`self-containment-reviewer` vs `documentation-reviewer`), (2) effort tier (high vs medium), (3) two-tier severity model, (4) whether the empty project plugin cache needs any action.
